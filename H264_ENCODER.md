# Enabling FFmpeg H.264 Encoder in WebRTC

This document explains how to modify the WebRTC build system to enable FFmpeg's H.264 encoder (libx264) instead of the default OpenH264 encoder.

## Current Architecture

WebRTC currently uses a hybrid approach for H.264 support:
- **Encoding**: OpenH264 library (`src/third_party/openh264/`)
- **Decoding**: FFmpeg library (`src/third_party/ffmpeg/`)

FFmpeg is configured with minimal features and only includes the H.264 decoder, not the encoder.

## Required Modifications

**Important Note**: Enabling FFmpeg's H.264 encoder is complex because WebRTC's FFmpeg is heavily customized with pre-generated configurations. The recommended approach is to use the existing OpenH264 encoder or implement a custom encoder wrapper. However, if you need to use FFmpeg's libx264 encoder, follow these steps:

### 1. Update FFmpeg Pre-generated Configurations

Since WebRTC uses pre-generated FFmpeg configurations, you need to modify the configuration files to enable H.264 encoder support. The configure command shown in `config.h` is just a comment - the actual configuration is done through `#define` statements.

#### 1.1 Understanding FFmpeg Configuration

FFmpeg configuration files use `#define` statements with values of 0 (disabled) or 1 (enabled). The key defines are:
- In `config.h`: General feature flags like `CONFIG_ENCODERS`, `CONFIG_LIBX264`
- In `config_components.h`: Individual codec components like `CONFIG_LIBX264_ENCODER`

#### 1.2 Modify Configuration Files

For each platform/architecture combination under `src/third_party/ffmpeg/chromium/config/Chrome/{platform}/{arch}/`, modify:

**1. `config.h`** - Main configuration file:
```c
// Find and change:
#define CONFIG_ENCODERS 0
// To:
#define CONFIG_ENCODERS 1

// Find and change:
#define CONFIG_LIBX264 0
// To:
#define CONFIG_LIBX264 1

// Also add if not present:
#define CONFIG_GPL 1  // Required for libx264
```

**2. `config_components.h`** - Component configuration:
```c
// Find around line 832 and change:
#define CONFIG_LIBX264_ENCODER 0
// To:
#define CONFIG_LIBX264_ENCODER 1
```

**3. `libavcodec/codec_list.c`** - Add libx264 encoder to the codec list:
```c
static const FFCodec * const codec_list[] = {
    &ff_h264_decoder,
    &ff_aac_decoder,
    &ff_flac_decoder,
    // ... other decoders ...
    &ff_libopus_decoder,
    &ff_libx264_encoder,  // ADD THIS LINE
    NULL };
```

**Important**: The `ff_libx264_encoder` symbol is defined in FFmpeg's source code (`libavcodec/libx264.c`). For this to compile:
1. The FFmpeg source must be built with `CONFIG_LIBX264_ENCODER=1`
2. The file `libx264.c` must be included in the build (handled by `generate_gn.py`)
3. libx264 headers and library must be available (see Section 3 below)

**Note about x264.h**: When `CONFIG_LIBX264_ENCODER` is enabled, FFmpeg source files like `libavcodec/allcodecs.c` will include `<x264.h>`. This header comes from the libx264 library itself, not from FFmpeg.

**Note**: These codec list files are typically auto-generated based on the configuration. After modifying the config files and running `generate_gn.py`, these files should be regenerated with the correct codec list.

#### 1.3 Alternative: Generate New Configurations

If you prefer to regenerate the configurations properly:

1. Clone FFmpeg source and checkout the version matching WebRTC's FFmpeg
2. Install libx264 development files
3. Run configure with encoder support:
```bash
./configure \
  --disable-everything \
  --enable-avcodec \
  --enable-avformat \
  --enable-avutil \
  --enable-static \
  --enable-pic \
  --enable-encoder=libx264 \
  --enable-libx264 \
  --enable-gpl \
  --enable-decoder='aac,h264,vorbis,libopus,flac,mp3,pcm_*' \
  --enable-demuxer='ogg,matroska,wav,flac,mp3,mov,aac' \
  --enable-parser='opus,vorbis,flac,mpegaudio,vp9,aac,h264' \
  --extra-cflags='-I/path/to/x264/include' \
  --extra-ldflags='-L/path/to/x264/lib' \
  --cc=clang \
  --cxx=clang++ \
  --ld=clang
```
4. Copy generated config files to WebRTC's FFmpeg config directories

### 2. Update FFmpeg Build Configuration

The FFmpeg build system consists of both manually maintained and auto-generated files:
- **Manually maintained**: `ffmpeg_options.gni` and `BUILD.gn` - you can modify these directly
- **Auto-generated**: `ffmpeg_generated.gni` - generated by `generate_gn.py` from the config files

#### 2.1 Regenerate Source Lists

After modifying the configuration files, you must regenerate the source lists:

```bash
cd src/third_party/ffmpeg
python chromium/scripts/generate_gn.py
```

This script processes the configuration files and generates `ffmpeg_generated.gni` with the appropriate source files based on the enabled features. It will automatically include libx264 encoder sources (like `libavcodec/libx264.c`) when `CONFIG_LIBX264_ENCODER` is set to 1.

#### 2.2 Modify `ffmpeg_options.gni` (Manual File)

Update `src/third_party/ffmpeg/ffmpeg_options.gni` - this file is manually maintained and can be edited directly:

```gn
declare_args() {
  # Existing args...
  
  # Add new argument to enable x264 encoder
  ffmpeg_enable_libx264_encoder = true
}
```

#### 2.3 Update `BUILD.gn` (Manual File)

Modify `src/third_party/ffmpeg/BUILD.gn` - this file is also manually maintained:

1. Add x264 as a dependency in the existing `deps` array (around line 230):
```gn
deps = [
  ":ffmpeg_features",
  "//third_party/opus",
]

# Add x264 dependency conditionally
if (ffmpeg_branding == "Chrome" && ffmpeg_enable_libx264_encoder) {
  deps += [ "//third_party/x264:x264" ]
}
```

3. Ensure encoder source files are included:
```gn
# The generate_gn.py script should have added these based on config.h
# but verify libx264.c is in the source list
```

### 3. Add x264 Dependency

The `<x264.h>` header file comes from the libx264 library, which must be added as a third-party dependency. This is a critical step - without it, FFmpeg won't be able to compile the libx264 encoder.

#### 3.1 Understanding the Dependency Structure

Looking at how FFmpeg integrates with opus in WebRTC:
- Opus is added as a dependency in the `deps` array: `"//third_party/opus"`
- The opus headers are found because the opus BUILD.gn exposes them through public_configs
- FFmpeg's configure was run with `--extra-cflags=-I/chromium/src/third_party/opus/src/include`

For x264, we need to follow a similar pattern.

#### 3.2 Add x264 as Third-Party Dependency

Following the pattern used by opus, you need to:

1. **Add x264 to `src/DEPS`**:
```python
  'src/third_party/x264': {
    'url': 'https://code.videolan.org/videolan/x264.git@stable',
    'condition': 'rtc_use_h264',
  },
```

2. **Run `gclient sync`** to download x264 source

3. **Build x264** (x264 uses its own build system):
```bash
cd src/third_party/x264
./configure --enable-static --enable-pic
make
```

4. **Create `src/third_party/x264/BUILD.gn`**:
```gn
config("x264_config") {
  include_dirs = [ "." ]  # x264.h is in the root directory
}

static_library("x264") {
  sources = [ "libx264.a" ]  # Pre-built static library
  
  public_configs = [ ":x264_config" ]
  
  # Make sure the headers are available
  public = [ "x264.h" ]
}
```

**Alternative: Use System libx264**

If x264 is already installed on your system, you could modify FFmpeg's BUILD.gn to use system libraries:
```gn
if (ffmpeg_branding == "Chrome" && ffmpeg_enable_libx264_encoder) {
  libs += [ "x264" ]  # Link with system libx264
  # You may need to add include paths depending on your system
}

Or copy the headers:
```sh
cp /usr/include/x264.h ./src/third_party/ffmpeg/libavcodec/
cp /usr/include/x264_config.h ./src/third_party/ffmpeg/libavcodec/
```
An modify the include:
/third_party/ffmpeg/libavcodec/allcodecs.c:807:10
```c++
#include "x264.h"
```

## Important Considerations

### 1. Licensing

- **libx264 is GPL-licensed**, which may conflict with your project's license
- Consider using OpenH264 (BSD license) or hardware encoders for commercial projects
- Ensure compliance with all applicable licenses

### 2. Binary Size

- Adding libx264 will increase the binary size significantly
- Consider using dynamic linking if size is a concern

### 3. Performance

- libx264 may provide better quality but could be slower than OpenH264
- Hardware encoders typically offer the best performance

### 4. Platform Support

- Ensure libx264 is available for all target platforms
- Some platforms (iOS, Android) may prefer hardware encoders

### 5. Testing

After making these changes:
1. Rebuild WebRTC with the new configuration
2. Test H.264 encoding functionality
3. Verify encoder selection (FFmpeg vs OpenH264)
4. Check performance and quality metrics

## Alternative Approaches

1. **Hardware Encoders**: Use platform-specific hardware encoders (VideoToolbox on macOS, MediaCodec on Android)
2. **Keep OpenH264**: It's already integrated and has a permissive license
3. **Custom Integration**: Create a plugin system for different H.264 encoders

## Verification

To verify the changes are working:

1. Check build output for libx264 inclusion
2. Look for "Creating H264 encoder" log message
3. Use WebRTC statistics API to verify encoder name
4. Inspect encoded bitstream for x264 headers

```cpp
// In your application
PeerConnectionInterface::Stats stats = pc->GetStats();
// Look for encoder stats showing "libx264" or "ffmpeg"
```
